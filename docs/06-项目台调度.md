# 06 · AI 项目台调度

目录：`skills/ai-dispatch/`
一句话：**老板说人话，项目台把话拆成任务卡，派人、验收、出日报。**

---

## 一、项目台底座

| 文件 | 作用 |
|---|---|
| `agents.md` | 宪法：分工、流程、红线 |
| `公共区/路由表.md` | 谁擅长什么 |
| `公共区/tasks/T<MMDD>-<序号>.md` | 任务卡 |
| `公共区/status.md` | 进度 |
| `公共区/dailylock.md` | 日报 / 卡点台账 |
| `公共区/result_index/` | 产物索引 |

没有就先建，不许空跑 —— 这是这套调度能长期用的前提。

---

## 二、触发词与动作

| 说 | 做什么 |
|---|---|
| 项目台：<需求> | 走完整五步调度 |
| 项目台：今天安排 | 报今天三件事，涉及干活的直接转任务卡 |
| 项目台：收工 | 汇总本轮产物 → 更新 status 与日报 → 报三句话 |
| 项目台：卡在哪了 | 读日报 + 进度 + 未完成任务卡，列出卡点 |
| 项目台：把 XX 加进来 | 更新路由表与成员表，回复已启用 |

---

## 三、五步调度

**第一步 读底**：先读宪法、路由表、日报。缺就建。

**第二步 拆单**：目标拆成 1–5 张任务卡，每张固定五段：

```
任务编号 / 目标 / 输入 / 验收标准 / 交付物
```

**第三步 派单**：按路由表派给擅长的一方，不越权。

**第四步 验收**：核对三件事 —— 目标达到没有、产物在哪、缺口怎么补。只说「已完成」不算交付。

**第五步 归档**：更新进度、日报、产物索引。

---

## 四、任务卡为什么强调验收标准

因为调度最容易烂的地方不是拆单，是「干完了吗」。

- 目标：要达到什么状态
- 验收：怎么判断达到了（可检查的条件，不是感觉）
- 交付物：具体文件在哪

三条缺一条，任务卡就是一句愿望。
