# 07 · 多租户交付（智慧大脑专家团）

目录：`skills/zhinao-expert-team/`
一句话：**建实例、喂资料、跑流水线、体检隔离、打包交付，一条龙。**

---

## 一、两层使用者

| 谁 | 需要什么 | 本技能怎么照顾 |
|---|---|---|
| 老板（人） | 只会说人话，不记命令 | 每个环节给「照着说哪句话」 |
| 专家团（AI） | 要命令与验收标准 | 每个环节给命令与验收口径 |

**铁规**：动作完成后，回复末尾必须给一段「你现在照着做」——用大白话说清：①现在你说哪句话（可直接复制）②你会看到什么 ③下一步建议。只报结果不给指引，等于没干完。

---

## 二、部署交付六步

| 步 | 做什么 | 关键动作 |
|---|---|---|
| 1 需求采集 | 行业、业务目标、输出风格、风控禁止条目、业务文档 | 一次问清，别反复打扰 |
| 2 资料预处理 | 整理切片，建客户独立向量库 | 一实例一向量目录 |
| 3 实例初始化 | 建独立实例、复制底层模板、替换业务参数、配人设与红线 | 先清主人人设 |
| 4 全流程测试 | 跑通全部工作流、多次自检、排 bug | 不通过不许交付 |
| 5 打包交付 | 导全套配置包、可解压本地部署、附操作教学 | 交付物是实例，不是账号 |
| 6 运维支持 | 远程更新工作流、升级自治规则、扩充知识库 | 按月做 |

---

## 三、实例隔离五条铁律

不可突破，客户也不能改：

1. **配置隔离**：一实例一 json
2. **向量库隔离**：单独目录，禁止跨实例检索
3. **人设隔离**：新建客户实例自动清主人人设，载客户专属人设
4. **日志隔离**：按实例目录分存
5. **权限隔离**：客户只能改自身业务资料，改不了底层调度引擎与自治规则

**版权归属**：底层框架归作者，客户只有使用权。合同里写清权限边界。

---

## 四、四大模块

| 模块 | 干什么 |
|---|---|
| 模型调度中枢 | 密钥管理 + 多模型路由；每实例独立配置；可新建 / 删除 / 备份 / 导出实例包 |
| 私有向量知识库 | 一实例一向量目录；批量导入 PDF / Word / 文本 / 脚本；只检索本实例资料 |
| 业务工作流引擎 | 触发事件 → 检索知识库 → 生成初稿 → 自治自检 → 输出 → 归档；可按行业改参数，底层流水线不变 |
| 自治模块 | 内容自检、日志归档、复盘微调（只微调文案与检索参数） |

---

## 五、软硬件前置

| 项 | 要求 |
|---|---|
| 载体 | 支持技能目录的 AI 客户端（如 Marvis + WorkBuddy） |
| 向量库 | Chroma |
| 模型 API | 按客户预算选，实例独立配置 |
| 硬件 | 最低 16G 内存，推荐 32G |
| 部署方式 | 客户单机本地部署、数据留本地；大客户可选轻量云 7×24 |

---

## 六、报价与合同提醒

- 报价区分「部署费」与「月度运维费」，运维按知识库扩充与规则升级计
- 合同写清：使用权范围、数据归属、模型额度谁付、交付后维护边界
- 不承诺效果数字（涨多少粉、涨多少营收），只承诺交付范围与验收标准
