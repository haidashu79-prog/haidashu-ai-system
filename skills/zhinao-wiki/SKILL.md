# 智脑知识库管理

一句话：**智脑负责搜和判，wiki 负责存和证；进得来、筛得掉、留得下。**

| | 智脑库（原料仓） | Marvis wiki（归档层，本技能管） |
|---|---|---|
| 位置 | `$WORKBUDDY_HOME/l3-core/brain/data/knowledge/items.jsonl` | `<实例根>/personal` + `/external` |
| 现状 | 349 条（2026-10-17 清水后：1121 → 349） |

| 谁写 | 脑自动写 | **只有通过筛选、老板认过的才写** |

**流水线**：智脑搜到的高价值料 → 过筛 → 进 wiki 长期归档；wiki 里沉淀出的认知 → 可反哺回智脑库。

**说"知识库"时**：默认指 Marvis wiki（本技能管的那层）；老板说"智脑自己那个库"时才指 items.jsonl。

## 二、四道关（干活按这个走）

### 第 1 关 · 找料（智脑搜）

```bash
# 先查重：本地有没有了（不联网）
sh "$B" knowledge --smart "<关键词>" --top 5
# 再补外料：多路渠道搜
sh "$B" search "<关键词>" --engine bing --limit 5
```

- 渠道按需换：`bing` / `so360` / `baidu` / `wx`（公众号）/ `csdn` / `juejin` / `bili` / `arxiv` / `wiki` / `gh`。
- **默认不加 `--keep`**：搜来的先过筛，过了才入库。加 `--keep` 等于绕过筛选，除非老板明说"先囤着"。
- 每条候选记齐：标题、来源、链接、抓取日期、一句话内容。
- 一次搜不满就换渠道再来一轮，**同一渠道同一词最多两轮**。

### 第 2 关 · 筛选（智脑判）

候选逐条过**四问**，见 `references/筛选汰换标准.md`：

1. **相关** —— 跟老板赛道沾不沾（一人公司 / AI 新媒体 / 口播 IP / 中年成长 / 民生评论）
2. **可信** —— 一手官方可追溯，还是网文互抄
3. **重复** —— 库里有没有、这批候选之间撞不撞
4. **有用** —— 能不能变成选题、话术、方法论，或者能直接引用；"知道也无所谓"的算没用

```bash
sh "$B" advise "逐条判四问，每条只回一行：收/弃 + 一句话理由。候选：<列表>"
```

**四问全过 → 收；③ 或 ④ 不过 → 弃；①② 存疑 → 挂「待观察」，本轮不入库。**

**personal 分区例外（安全硬线）**：老板的私人材料**不许喂给 `advise`**（它会联网、可能走云端模型）。personal 的筛选只用本地查重 `knowledge --smart` + 老板人工判断，除非老板就某一批单独授权。

### 第 3 关 · 编译（入库 + 落 wiki）

```bash
python3 "$MW/scripts/marvis_wiki.py" ingest "<源文件或目录>" \
  --partition external --category topics --collection <小写英文集合id>
python3 "$MW/scripts/marvis_wiki.py" lint
```

- `raw/` 拷进去就**只读**：不覆盖、不改写、不搬走、不删（除非走第 4 关的确认流程）。
- 拷完必须**真编译**：写 wiki 页 + 更 index + 记 log，三样齐了才算写完。
- wiki 页的每条论断都要带 `raw://...` 引用；拿不到出处的内容**不许编摘要**，如实标"未编译"。
- **external 分区绝不引用、不复制、不摘要 personal 材料**；外部知识怎么用在老板身上，写进 personal。

### 第 4 关 · 汰换（智脑体检，老板拍板）

体检四查：**重复 / 低价值 / 过期 / 未编译**。

```bash
python3 "$MW/scripts/marvis_wiki.py" lint                                          # 结构问题
sh "$B" advise "给这批条目做体检，分三档：留/观察/建议删，每条一句话理由。条目：<列表>"
```

- 出**三档清单**：留 / 观察 / 建议删（判据见 `references/筛选汰换标准.md`）。
- **「建议删」必须老板点头才动手**，这是硬纪律，不许自动删、不许批量静默清。
- 老板确认后，一条一条走官方流程：

```bash
python3 "$MW/scripts/marvis_wiki.py" remove-plan "<raw://...>" --json   # 先出影响面给老板看
python3 "$MW/scripts/marvis_wiki.py" remove "<raw://...>" --confirm <TOKEN> --json
python3 "$MW/scripts/marvis_wiki.py" lint                                # 删完修索引再校验
```

- 删完要**修受影响的 wiki 页和索引**，再跑 lint。
- 淘汰 ≠ 销毁：优先「移出归档」（从 wiki 撤下、raw 保留），只有确认彻底没用才真删。
- 每轮淘汰后回执给脑，它才学得会：

```bash
sh "$B" feedback <主意编号> 采纳|没做|没用 "<说明>"
```

## 三、智脑调用点汇总

| 关 | 干什么 | 命令 | 注意 |
|---|---|---|---|
| 1 | 本地查重 | `knowledge --smart "<词>" --top 5` | 不联网，personal 可用 |
| 1 | 外部补料 | `search "<词>" --engine <渠道> --limit 5` | 默认不加 `--keep` |
| 2 | 逐条筛选 | `advise "四问逐条判…"` | **personal 禁用** |
| 3 | 出启示 | `digest --dry-run` 先看清单，再 `digest --limit N` | 只喂 external |
| 4 | 体检分档 | `advise "…体检分三档…"` | personal 只做本地结构查 |
| 4 | 回执 | `feedback <编号> 采纳|没做|没用 "<说明>"` | 每轮至少回一条 |

**`advise` 返回长什么样**（2026-10-17 实测）：

```
① 先看自己懂不懂：知识库命中 N 条     ← 它自己会先查本地库，等于自带查重
② 人性这一关（受众：…）
③ 主意：结论 + 2~3 条动作（每条带"为什么"+"今天就能做"）
④ 坑
⑤ 还缺什么（下次该去搜的）           ← 直接当下一轮搜索词用
⑥ 今天第一件事
⑦ 主意编号 xxxx + feedback 提示
```

筛选场景怎么取：**③ 的结论 = 收/弃判定，④ = 风险提示，⑤ = 下一轮搜索词，⑦ 的编号要回执**。

**降级纪律**：`advise` / `search` 走不通（没网、超时、报错）时，落到本地规则档（`references/筛选汰换标准.md` 的判据 + `lint`），并**在交付里写明"这轮没上脑，走的是规则版"**，不许装作用过。
**别用 `chat`**：运行区 brain.py（0.17.1）没有这个子命令，会直接报错。
**别用 `timeout`**：macOS 上没这个命令，会直接 `command not found`；要限时用 `perl -e 'alarm N; exec @ARGV' -- <cmd>`。

## 四、交付格式

每轮干完，按这个报：

```
## 一、这轮动了什么
（实例根 / 分区 / 集合 / 新增几条 / 淘汰几条 / 编译了几页）

## 二、筛选台账
（表格：候选 / 来源 / 四问结果 / 收·弃·观察 / 一句话理由）

## 三、体检报告（做汰换时才有）
（三档：留 N 条 / 观察 N 条 / 建议删 N 条，逐条理由；等老板拍板）

## 四、lint 结果
（结构问题清单，没有就写"干净"）

## 五、脑这轮干了什么
（哪几步上了脑、哪几步走了规则版、回执编号）
```

## 五、红线

1. `raw/` 只读，移除必须「preview → 老板确认 → 执行」三步，禁止静默删。
2. **老板的私人材料不上网、不出本机**：不喂 `advise`、不喂搜索、不喂远程模型。
3. `external` 里绝不出现 personal 的内容；personal 可以引用 external。
4. 不自动保存对话；只有老板明确说要留，才往库里写。
5. 拿不到来源就写「未编译 / 未获取」，**不许编摘要、编链接、编数据**。
6. 目录非空且不是合法实例，不覆盖，停下来问。
7. 淘汰永远给老板看清单，不许自己拍板删。
